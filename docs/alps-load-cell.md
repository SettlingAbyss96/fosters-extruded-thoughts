# Mellow ALPS: signal-only, or real load-cell data?

**Answer: both, depending on firmware.** Out of the box it only sends a trigger signal. **Reflashed with Klipper**, it streams raw load-cell data to Klipper's native `[load_cell_probe]`. That's what autopa (automatic PA) and proper load-cell probing need.

*Researched 2026-10-01.*

## Two modes

| | Stock Mellow firmware | Klipper firmware (reflashed) |
|---|---|---|
| What Klipper gets | **Digital trigger only**, on a probe pin | **Raw 24-bit force data** streamed over USB |
| Klipper config | `[probe] pin: ^PA10` + `[output_pin _probe_ready]` (enable pin) | `[mcu alps]` + `[static_pwm_clock]` + `[load_cell_probe] sensor_type: ads131m02` |
| Trigger threshold | Set on the module itself (Mellow's USB tool) | `trigger_force` in grams, in Klipper |
| Works as a Z probe | ✅ (like any switch probe) | ✅ (native load-cell probe, with tare on every tap) |
| Auto PA (autopa) | ❌ no force data | ✅ |
| Load-cell diagnostics (`LOAD_CELL_READ`, `LOAD_CELL_DIAGNOSTIC`) | ❌ | ✅ |
| Wiring to the printer | 1.5 m signal cable to a mainboard/toolboard port | USB-C data cable to the Pi |

**We want the Klipper-firmware mode.**

| Piece | Mainline Klipper | Kalico |

| `static_pwm_clock` (8 MHz ADC clock on `PA3`) | ✅ since 2025-10 | ✅ |

## Hardware facts (from autopa's ALPS guide)

| | |
|---|---|
| MCU | **STM32F072**, 8 MHz crystal. Same chip as the LLL Plus buffer. |
| ADC | **ADS131M02**, 24-bit, SPI (`spi1_PB4_PB5_PB3`, CS `PA15`, data-ready `PB6`), gain 128 |
| Clock | 8 MHz master clock generated by the MCU on `PA3` |
| Flashing | **ROM DFU over USB-C** (BOOT + RESET buttons); no bootloader offset |
| Sample rate | about 488 SPS |
| Calibration | `counts_per_gram: 138` is a property of the module and reusable as-is; `reference_tare_counts` is set once per machine with `LOAD_CELL_CALIBRATE` |
| Probe performance (autopa author's machine) | Repeatability **≈0.005–0.008 mm** per tap at bed centre; looser at flexible bed corners |

## Setup outline

Full steps: [autopa `docs/ALPS.md`](https://github.com/G0BL1N/autopa/blob/main/docs/ALPS.md) and [`docs/PROBE.md`](https://github.com/G0BL1N/autopa/blob/main/docs/PROBE.md).

1. Hold BOOT, tap RESET, release BOOT. Check that `lsusb` shows `0483:df11`.
2. `make menuconfig`: STM32, **STM32F072**, **8 MHz crystal**, **USB (PA11/PA12)**, **No bootloader**. Save it to `firmware/alps-klipper.config`.
3. `sudo make flash FLASH_DEVICE=0483:df11`. A final `dfu-util: Error during download get_status` is expected and harmless.
4. Config:
   ```ini
   [mcu alps]
   serial: /dev/serial/by-id/usb-Klipper_stm32f072_<ID>

   [static_pwm_clock alps_clk]
   pin: alps:PA3
   frequency: 8000000

   [load_cell_probe]
   sensor_type: ads131m02
   cs_pin: alps:PA15
   spi_bus: spi1_PB4_PB5_PB3
   data_ready_pin: alps:PB6
   gain: 128
   pwm_clock: static_pwm_clock alps_clk
   adc_channel: 0
   counts_per_gram: 138
   trigger_force: 200
   speed: 0.5
   lift_speed: 5
   tare_time: 0.1
   z_offset: 0.0
   ```
5. Check it: `LOAD_CELL_READ LOAD_CELL=load_cell_probe`, then `LOAD_CELL_DIAGNOSTIC` (about 488 SPS, 0 saturated samples). Then run `LOAD_CELL_CALIBRATE`.
6. Install autopa (`install.sh`, which adds numpy to the Klipper venv).

**Tips from the autopa author:**
- Probe slowly (about 0.5 mm/s).
- Set `second_homing_speed` to the probe speed.
- **Don't** enable `drift_filter_cutoff_frequency`. It can miss real contact at flexible bed corners and drive the nozzle into the bed.

## What this changes in the build

- **The Klicky dock, `klipper_z_calibration` (auto-Z) and the Z endstop pin all go away.** The nozzle is the probe, so there's no separate Z offset to drift.
- **A USB cable has to run to the toolhead.** The toolhead is CAN today, so the umbilical needs a USB-C data line, with good strain relief and routed away from stepper wires. Alternative: a small USB hub on the toolhead.
- That puts **three USB Klipper MCUs** on the Pi (Octopus, ALPS, LLL Plus) plus the U2C. That's fine on a Pi 5.
- **It can be undone.** Mellow's firmware can be reflashed over DFU at any time ([Mellow ALPS docs](https://mellow.klipper.cn/en/docs/category/alps-%E5%8E%8B%E5%8A%9B%E8%B0%83%E5%B9%B3%E6%A8%A1%E5%9D%97-/)).

## Still to verify

- [ ] **The HeatCore 4 UHF ALPS uses the same ALPS board as the ALPSv6** that autopa validated: STM32F072 + ADS131M02, with USB-C and BOOT/RESET buttons reachable once installed. The product page lists the same ADC and a USB port, which is promising but not proof.
- [ ] **Temperature rating of the ALPS electronics** in a 75 °C chamber, sitting on a heatsink next to a 350 °C hot zone. Ask Mellow. Tare-on-every-tap cancels slow thermal drift, but the electronics still have a temperature limit.
