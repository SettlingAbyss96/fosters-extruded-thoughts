# Contributing

Corrections, papers I missed, and "that's not how it works" are all welcome. Open an issue, or a
pull request if you've got the fix.

## How the docs are written

- **Casual first person.** Write like you're explaining it to a friend at the bench. "This is why", "I think", "here's the catch"
- **Explain the why**, not just the setting. If a number shows up, say where it comes from
- **Say when something is a guess.** Mark your own theories as theory. Link the paper when something is established
- **No em dashes.** Use commas, colons, parentheses or a new sentence
- **Math in LaTeX.** Inline math goes in `` $`...`$ ``, like `` $`\tau\,\dot{q}`$ ``, and display math in a ```` ```math ```` block. Both reach MathJax exactly as written, so normal LaTeX works. Skip bare `$...$` and `$$...$$`: Markdown eats the backslashes, `*` and `_` in them. GitHub also refuses a few macros. `\operatorname` is the one you'll hit, so write `\mathrm{rank}` instead. And inside a ```` ```math ```` block, a `<` right before a letter gets read as an HTML tag, so write `\lt` or put a space after it
- **Figures come from code.** Plots are generated by [`handbook/figures/make_figures.py`](handbook/figures/make_figures.py) from the same toy models the chapters use, so changing a number means rerunning the script
- **Cite with links.** Title, authors, venue and year, and a DOI or official page where there is one

## Before you push

```bash
python tools/check_docs.py
```

It checks the LaTeX quirks above, broken relative links and missing anchors, em dashes and stray
control characters. `--fix` rewrites bare `$...$` inline math into the `` $`...`$ `` form for you.
